# Payment integration security notes

Sandbox checkout is opt-in. Never enable production Paystack keys in this implementation. Checkout email is passed to Paystack; do not log it. Customer access tokens must remain private.

**Blocking limitations:** no fulfillment, no customer authentication, no provider-independent reconciliation, and no production hardening. The public status endpoint uses a bearer capability token. Treat it as sensitive. Existing transactions created before migration have no token and cannot be queried through the new authenticated route.

Payment confirmation must use server-to-server verification, never browser redirects. Webhook signatures alone are not sufficient for settlement proof.
